# Tester Mode

Активный режим включает подробную диагностику. В личном чате доступны `/export` (ZIP за 30 дней), `/export recent` (JSON за 24 часа, до 100 событий) и `/export last` (JSON последнего пользовательского запроса). Отправка документа идёт через outbox. `/tester_off` прекращает подробный сбор и отменяет ожидающие экспорты, сохраняя записанную историю. `/tester_reset` и `/tester_delete_all` очищают новый диагностический журнал. Правило для прежних событий Inbox описано отдельно ниже. [Диагностика и экспорт](../diagnostics.md)

Tester Mode помогает повторно проходить первый запуск и проверять сценарии OwnDay на собственном Telegram-аккаунте. Команды доступны в личном чате с ботом. Авторизация привязана к числовому Telegram User ID.

## Команды

| Команда | Действие |
|---|---|
| `/tester` | Запрашивает секретный код отдельным сообщением. При активном доступе показывает список команд. |
| `/tester_status` | Показывает количество задач и программ, прогресс выбранной программы, состояние упражнений и диалога и число учебных запросов в очереди или обработке. |
| `/tester_reset` | Сбрасывает данные для повторного первого запуска. Нажмите «Сбросить мои данные», затем отправьте `/start`. |
| `/tester_delete_all` | Удаляет пользовательские данные и историю из рабочей PostgreSQL. Нажмите «Продолжить удаление моих данных», затем отправьте `DELETE` отдельным сообщением заглавными латинскими буквами. |
| `/tester_off` | Отзывает доступ Tester Mode и закрывает открытое подтверждение. Пользовательские данные сохраняются. |
| `/cancel` | Закрывает активный запрос кода или подтверждение. В обычном диалоге сохраняет своё учебное действие. |

Подтверждение действует 120 секунд по умолчанию, включая оба шага удаления. Неверная контрольная фраза закрывает сценарий удаления. Для новой попытки снова отправьте `/tester_delete_all`. Кнопка действует один раз для конкретной операции и владельца.

## Включение и секрет

Режим по умолчанию выключен. Сгенерируйте для каждой среды отдельный код из 32 случайных байт, закодированных 64 шестнадцатеричными символами с префиксом `ownday-tester-`. Вычислите SHA-256 от строки целиком, включая префикс и без перевода строки. Например, в локальной оболочке с OpenSSL:

```sh
tester_code="ownday-tester-$(openssl rand -hex 32)"
tester_hash="$(printf '%s' "$tester_code" | openssl dgst -sha256 -r | cut -d ' ' -f 1)"
```

Храните значение `tester_code` в менеджере секретов. Передавайте приложению только значение `tester_hash`. Для Production используйте закрытый runtime-файл `.env` на VPS. [Runtime-конфигурация Production](../../deployment/GITHUB_SECRETS.md#runtime-secrets)

| Переменная среды | Значение |
|---|---|
| `TesterMode__Enabled` | `true` для включения, `false` для выключения. |
| `TesterMode__SecretHash` | SHA-256 в виде 64 шестнадцатеричных символов. Обязателен при включении. |
| `TesterMode__ConfirmationTimeoutSeconds` | Срок ввода кода и подтверждений от 10 до 600 секунд. По умолчанию 120. |

OwnDay проверяет код до передачи текста в Learning. После обработки бот пытается удалить сообщение с кодом согласно ограничениям Telegram API. После пяти ошибок в течение 15 минут нужно дождаться конца этого окна. Запрос нового кода и перезапуск сохраняют счётчик. [Telegram Bot API — удаление сообщений](https://core.telegram.org/bots/api#deletemessage)

Авторизация переживает перезапуск, сброс, удаление и замену хеша. Для отзыва собственной авторизации используйте `/tester_off`. Установите `TesterMode__Enabled=false` и перезапустите приложение, чтобы приостановить все команды и кнопки Tester Mode. При повторном включении прежние авторизации снова действуют, а открытые подтверждения сохраняют исходный срок.

## Сброс и удаление данных

Обе операции физически удаляют задачи и проекты, прежние записи Inbox и связанные результаты обработки, программы и маршруты, упражнения и попытки, Evidence, состояние освоения навыков, историю взаимодействий, расписания, диалоги, язык и предпочтения. Также удаляются учебные запросы владельца, их технические попытки и прежние сообщения владельца в outbox. После этого `/start` показывает первый запуск.

`/tester_reset` сохраняет диагностические события Inbox с кодами, временем и идентификаторами. `/tester_delete_all` удаляет и эти события владельца. Обе операции сохраняют запись доступа Tester Mode, маркеры дедупликации Telegram без текста и агрегаты бюджета LLM по пользователю и месяцу UTC. Агрегаты содержат число вызовов, токены, расходы и отметку неизвестной стоимости. Новый ответ об операции записывается в outbox. Область удаления ограничена рабочей PostgreSQL. Уже доставленные сообщения Telegram, резервные копии, логи, внешние сервисы, глобальные записи и данные других пользователей остаются вне этой операции.

Очистка и её ответ фиксируются в одной транзакции. Учебный запрос, удалённый во время очистки, теряет право сохранить результат по ранее выданному lease. Уже отправленный запрос к LLM может завершиться у провайдера. OwnDay завершает очистку независимо от такого вызова и сохраняет учтённую резервацию.

## Production и проверка с NVDA

Примените миграции `20261120130000_AddTesterMode` и `20261120140000_AddTesterReset` перед запуском новой версии. После изменения `.env` пересоздайте контейнер командой `docker compose up -d --force-recreate app`, чтобы приложение получило новые значения. Для отката после очистки используйте версию, которая учитывает сохранённые агрегаты бюджета. [Порядок применения миграций](../../deployment/GITHUB_SECRETS.md#database-migration) · [Учёт бюджета LLM](../learning/cost-control.md)

На тестовом боте откройте Telegram Desktop с NVDA и пройдите команды с клавиатуры. Проверьте, что NVDA читает цель каждой кнопки и последствия действия, объявляет отдельный запрос `DELETE` и позволяет ввести фразу и `/cancel`. Повторно нажмите кнопку из старого сообщения и проверьте, что бот сообщает о завершении или истечении подтверждения.
