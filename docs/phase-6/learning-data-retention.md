# Хранение и удаление учебных данных

Карта текущей схемы для D08. Пользовательская операция удаления ещё недоступна. Учебная история хранится до явного действия владельца.

| Хранилище | Данные и зависимость при удалении |
|---|---|
| `learning_programs`, `learning_routes` | Цель и её критерий, диагностика, все версии маршрута и тексты тем. Владелец определяется по программе. Связь с проектом OwnDay сохраняет границу между учебной программой и данными самого проекта. |
| `learning_contexts`, `dialogue_contexts` | Выбор программы, цель консультации, уточнение, подтверждение и привязки к опубликованному вопросу. Контекст диалога общий для владельца. Для частичного удаления требуется очистить связанные поля с учётом версии сохранённого состояния. |
| `learning_lessons`, `learning_interactions`, `learning_sessions` | Материал, рубрика, ответы, пояснения, происхождение фактов, сводки и возобновление. Есть уроки без программы. При удалении всей истории они входят в область владельца. |
| `learning_evidence`, `learning_skills`, `learning_program_skill_links`, `learning_reviews` | Ответы и основания оценки, история апелляций, связи с версиями маршрута и расписание повторений по навыку. Удалить свидетельства удаляемых уроков и пересчитать статус и даты у сохранившихся навыков. Для названий и описаний навыков также нужна проверка происхождения: они могут содержать текст удаляемой программы. |
| `learning_preferences`, `learning_study_schedules` | Явные предпочтения, согласие на напоминания, последнее приглашение и привязки к программе и уроку. Частичная операция должна сохранить согласие владельца и снять затронутое приглашение. |
| `learning_requests`, `learning_provider_steps` | Нормализованный текст, аргументы, результат диалога, снимки целей и материала, результаты провайдера. Владение задано в запросе. Программа может быть указана только внутри JSON или определена позднее при исполнении. Для будущих записей нужна структурированная область. Для старых строк требуется разбор всех поддерживаемых версий и политика для неоднозначных случаев. |
| `learning_applied_operations`, `learning_provider_attempts`, `openai_request_attempts`, `processed_telegram_updates` | Маркеры применения, lease, идентификаторы для дедупликации, токены и суммы. Внешний ключ ledger удерживает запись физической попытки. Сохранение действующих бюджетных ограничений и защиты от переигрывания требует отделить минимальные технические записи от учебных payload. |
| `telegram_outbox_messages` | Готовые тексты и кнопки. Обычные ответы могут ссылаться на learning request, а приглашения имеют отдельную привязку. Текущая очистка удаляет отправленные записи через 30 дней. Неотправленные и уже захваченные на доставку записи требуют отдельной проверки перед отправкой. |

Подтверждение и транзакция удаления должны использовать один owner fence с обработкой Learning. После фиксации удалённая работа не должна восстанавливаться через запоздалый apply или replay. Для минимальных записей дедупликации срок нужен в связи с окном повторной доставки и восстановления из резервной копии. Окно месячного LLM-бюджета должно переживать удаление учебных текстов.

Резервные копии требуют журнала подтверждённых удалений вне восстанавливаемой базы. Перед открытием восстановленной среды для webhook, worker и outbox нужно применить события удаления, произошедшие после копии, и проверить их результат. Точный срок выбытия копий требует подтверждения по действующей политике PostgreSQL и архивам. Ограничения уже доставленных сообщений Telegram и обработки копий у LLM-провайдера должны быть указаны в предпросмотре операции с учётом фактической конфигурации.
