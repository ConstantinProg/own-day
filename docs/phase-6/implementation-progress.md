## Проверки M01

- На исходном коде `Post_MarketGoalRestatementAndShortExperience_StartsExerciseOnResume` не находит сохранённую программу после точной реплики из плана.
- Первая проверка исправления — 13 hosted-тестов прошли с детерминированным провайдером. В набор вошли консультация, новый старт программы, общая и авторская диагностика.
- Первый полный прогон на Windows исчерпал локальные TCP-порты при выключенном пуле Npgsql. Прогон 770 unit-тестов прошёл, интеграционный результат непригоден для приёмки. Повторный прогон использует ограниченный пул.
- Повторный полный прогон с пулом — 770 unit-тестов и 451 интеграционный тест прошли, два live-теста пропущены. Выявлен лишний вызов LLM на «Продолжим» при отсутствии программы. Исправлено, что контрольная реплика возвращает к вопросу о цели без обращения к провайдеру.
- Архитектурное ревью проверило привязку к программе, сохранение вопроса при чтении прогресса и совместимость уже сохранённых контрольных отпечатков. Добавлено ограничение отката миграции для программ с записанным критерием цели.
- Последняя сборка Release прошла без предупреждений. 18 целевых интеграционных тестов прошли на PostgreSQL 17, включая английский старт, mixed-ввод, отказ планировщика, перезапуск, подтверждённую смену цели, повторы и защиту от потери критерия при откате.
- Полный прогон коммита прошёл 770 unit-тестов и 449 интеграционных. Два live-теста пропущены. Четыре теста получения lease в Inbox и Learning упали, причины уточняются на изолированном повторе.
- Язык начальных сообщений определяется исходной целью. При оценке провайдер получает указание сохранять язык материала независимо от языка ответа. Запрос объяснить на другом языке действует для текущего пояснения. Пользовательская сквозная проверка языка и качества с подключённой моделью остаётся открытой.
- Для live-качества, Telegram Desktop и NVDA требуются отдельные прогоны.

## Проверки M02

- Исходный hosted-тест ожидал второй вопрос TypeScript, но после ответа PostgreSQL по-прежнему содержал первый вопрос.
- Проверены граница пяти вопросов, запрет повторного вопроса и преждевременного вывода об уровне, отказ от результата с некорректной формой, сохранение наблюдений и вопроса при перезапуске. Поздняя диагностика по биржевым заявкам завершилась после двух ответов и сохранила версию уже начатого маршрута. Диагностика не создаёт записи mastery.
- 49 целевых интеграционных тестов на PostgreSQL 17 прошли. Набор включает изолированный повтор четырёх упавших тестов получения lease из полного прогона. Проверка педагогического выбора вопросов реальной моделью остаётся открытой.
- Существующий одиночный вопрос и авторская English-ветка читаются прежними сценариями. Новая диагностика включена для программ из консультации. Новый формат хранит исходные ответы в PostgreSQL, а планировщику передаёт текущий ответ и краткие предыдущие наблюдения. Откат миграции блокируется при наличии новых диагностических данных.

## Проверки M03

- Для новой рубрики рассчитаны отдельные пороги: два самостоятельных различных упражнения на понимание, одно самостоятельное применение, одно самостоятельное повторение по тому же навыку спустя как минимум сутки. Повтор вопроса или нормализованного ответа, помощь и неразрешённое противоречие не дают подтверждённого Mastery. Прежние записи сохраняют свою семантику.
- Hosted-сценарий TypeScript проверил публикацию критерия, сохранение исходного ответа с уточнением, восстановление после перезапуска, итоговую оценку и идентификатор операции, отсутствие дубля при повторе. Два ответа в рамках уточнения формируют одно свидетельство. Невозможность сделать вывод после уточнения сохраняется отдельно от отрицательного результата и оставляет расписание повторений без изменений.
- Архитектурное ревью выявило, что сравнение уточнения с эталоном исходного вопроса создавало бы ложный конфликт. Детерминированная проверка теперь использует исходный ответ. Адаптер отклоняет новый материал без корректной рубрики, а уже сохранённый материал остаётся читаемым.
- Release-сборка прошла без предупреждений. Прошли 776 unit-тестов и 19 целевых интеграционных проверок с PostgreSQL 17, включая старые данные, рестарт с уточнением и деградацию при отказе источника.
- Статус практической цели показывается как ожидающий прямой проверки. Сквозная проверка практической цели и экспертный набор для RU/EN/mixed остаются открытыми.

## Проверки M04

- Сессию закрывает явное действие или два часа без нового учебного сообщения. Простой учитывается по времени получения запроса. Активное время включает интервалы между репликами до пяти минут. При обнаружении простоя сохраняется фактическая граница истечения.
- PostgreSQL сохраняет ограниченную сводку с идентичностью урока, версией маршрута, темой и вопросом. При возврате диалог читает актуальное упражнение. Просроченное сообщение сначала получает его резюме без оценки. Чтение прогресса не продлевает сессию.
- Сборка Release прошла без предупреждений. Четыре целевых unit-теста и 15 интеграционных проверок прошли. Hosted-тест подтвердил явное закрытие, перезапуск, истечение двух часов, сохранение вопроса и оценку только свежего ответа. Для учебной сводки не требуется вызов провайдера.
- Миграция добавляет таблицу с FK на программу того же владельца и защищает непустую историю при откате. Отдельная проверка понимания по возвращении и пилот доступности остаются открытыми.

## Проверки M05

- После двух шагов помощи можно ответить самостоятельно, отложить или завершить упражнение. Полное решение выдаётся по прямому запросу. Повторный запрос показывает сохранённое решение. Промежуточные ответы и выбранные подсказки сохраняются в оценочном снимке без отдельного mastery evidence.
- Подсказка и полный ответ отмечают помощь на уровне Domain. Удачное исправление закрывает упражнение и предлагает другое задание для самостоятельной проверки; оценка с помощью не подтверждает владение.
- Архитектурное ревью проверило смену привязки при каждой коррекции и отделило новый самостоятельный ответ от старого уточнения при проверке эталона. Откат блокируется при наличии истории коррекций или полного решения.
- Сборка Release прошла без предупреждений. Прошли 778 unit-тестов и 9 целевых интеграционных проверок PostgreSQL. Hosted-тест подтвердил сохранение ответа после сбоя apply, повторное применение сохранённого результата без повторного вызова, восстановление подсказки, ограничение помощи, единственную выдачу решения через провайдера и единственную итоговую запись с помощью.
- Текстовая педагогическая оценка адресности подсказок на реальной модели остаётся открытой.

## Проверки M06

- Изменение спорной оценки проверяется второй отдельной оценкой по исходной рубрике, если детерминированный результат не даёт достаточного основания для решения. Разногласие оставляет прежний зачёт. Проверяющие вызовы получают исходный ответ и аргумент без старых оценочных отметок.
- При применении новой оценки расчёт зачёта, Mastery и расписания использует единственное действующее решение. Исходные оценки и прежние версии сохраняются. При пересчёте сохраняется явно отложенный срок повторения.
- Ревью устранило риск подмены рубрики при повторной оценке: проверяющий получает рубрику из исходного свидетельства. После коррекции оценивается итоговый ответ, а при завершении через уточнение передаются обе соответствующие реплики.
- Сборка Release прошла без предупреждений. 779 unit-тестов и 12 целевых интеграционных проверок прошли. Hosted-сценарий подтвердил отказ apply без частичных записей, повтор без лишних вызовов, защиту от чужого владельца и устаревшей версии, сохранение первичной оценки и согласованное обновление покрытия и срока повторения.
- Экспертная оценка формулировок и качества апелляции с живой моделью остаётся открытой. Повторная проверка использует отдельный вызов и отдельный контекст текущего провайдера.

## Проверки M07

- Решение D05. Порядок, пропуск и глубина сохраняют код и смысл темы внутри одного `ProgressRootVersion`. Существующие корни, созданные диагностикой, не смешиваются. Откат добавляет версию с указанием исходной версии и её корня. Опубликованные задания, рубрики и свидетельства сохраняют свою версию.
- Пропуск служит явным разрешением перейти к зависимым темам. Проверка пропущенной предпосылки доступна по запросу как отдельное упражнение. Зачёт оформляется по результату попытки. Ручная перестановка сохраняет порядок предпосылок. Параметры правки требуют подтверждения для текущей программы и версии.
- Метаданные маршрута добавлены совместимой nullable-колонкой. На заполненной базе проверены обратная и прямая миграции. Откат схемы блокируется при наличии сохранённых правок.
- Сборка Release прошла без предупреждений. Прошли 782 unit-теста и три целевые интеграционные проверки с PostgreSQL 17.12. Проверены 07.1 и 07.2, в том числе смена текущей версии между публикацией и подтверждением правки.
- В расширенном прогоне прошли 164 интеграционных теста, один live-тест пропущен. Первый прогон исчерпал общий лимит подключений PostgreSQL из-за отдельных пулов для тестовых схем. Повтор использовал `Connection Idle Lifetime=2;Connection Pruning Interval=1`.

## Проверки M08

- Небольшая адаптация использует существующий предел повторяющегося пробела и только допустимые темы. Предпросмотр существенной правки содержит цель, критерий и полный набор тем. Подтверждение сохраняет точный снимок и версию программы. Новая программа может принять критерий из явной реплики. Исторические подтверждения старого формата читаются прежним путём.
- Для совпадающего набора идентичностей сохраняется корень зачёта. Другой набор получает собственный корень. История исходной цели, критерия, упражнения и evidence сохраняется. Откат возвращает цель и критерий выбранной версии. Данные расширяют совместимый JSON маршрута в существующей колонке.
- Ревью выявило два пути неправильного применения. Версию новой цели нельзя применить как малую адаптацию. Упражнения для новой цели не получают старую диагностику или авторский урок, привязанный к ней.
- Release-сборка прошла без предупреждений. Прошли 45 целевых unit-тестов и 7 интеграционных проверок PostgreSQL, включая повтор подтверждения после рестарта, отказ планировщика, атомарный сбой и последующий откат. Экспертная оценка уместности автоматической адаптации остаётся открытой.

## Проверки M09

- Поиск учитывает названия и дисциплины только собственных программ. Неоднозначность показывает до пяти вариантов и текстовый способ уточнить выбор. Конкретная программа использует прежнее подтверждение по ID, версии и учебному вопросу.
- Старое упражнение остаётся доступным с исходной рубрикой. При пропуске его темы или смене корня зачёта диалог поясняет расхождение и даёт команды для перехода на новый маршрут.
- Явная связь навыка раскрывает основание. Для переноса требуется подтверждённое независимое evidence, действующий срок повторения и подтверждённое извлечение навыка не старше 30 дней. Устаревшая, противоречивая или предварительная оценка предлагает отдельную проверку.
- Ревью исключило обновление свежести повторным ответом на старый вопрос. Перенос использует те же условия независимости, что и Mastery.
- Сборка Release без предупреждений, 787 unit-тестов и 9 интеграционных проверок PostgreSQL прошли. Проверены 09.1–09.2, включая неоднозначное название и изоляцию владельца, перезапуск, сохранение подсказки и рубрики упражнения из bounded practice, предупреждение о другой версии и перенос только с достаточным evidence.

## Проверки M10

- До трёх вариантов в одном ответе. Наступившие сроки упорядочены по давности. При наличии места добавляется одна контекстная проверка предпосылки на основе действующих оценок. При возврате без открытого упражнения варианты доступны независимо от напоминаний.
- Ревью выявило, что отложенный срок мог сразу повторно появиться как контекстная практика. Выбор теперь проверяет его по естественному расписанию из истории. Перенос и пересмотр используют один детерминированный расчёт срока.
- Проверены 10.1–10.2. Сборка Release без предупреждений, 21 целевой unit-тест и 5 интеграционных проверок PostgreSQL прошли. Сквозной сценарий проверил порядок, различие due и предпосылки, перенос, повторную команду, единственную генерацию и сохранение старого свидетельства после ошибки.

## Проверки M11

- Приоритет параметров пояснения — текущая просьба, явная настройка дисциплины, явная общая настройка, повторяющийся сигнал. Для повторяющегося сигнала нужны согласованные просьбы на трёх разных упражнениях среди 30 последних пояснений в этой области. Лимит времени остаётся ситуативным. Сброс прекращает учитывать прежние сигналы и сохраняет учебную историю.
- Снимок отданного пояснения сохраняется рядом с учебной репликой. Сами настройки не меняют оценку, расписание или содержание опубликованного вопроса. Помощь в ответе по-прежнему учитывается правилами упражнения.
- Ревью проверило, что конфликтующие просьбы внутри упражнения исключают устойчивый сигнал, а сброс начинает действовать и для уже открытого урока. Миграция сохраняет общие строки, добавляет предметную область и защищает содержательные снимки при откате.
