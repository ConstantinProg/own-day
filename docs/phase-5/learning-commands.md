# Урок, программа, персональная модель знаний и расписание

Команды работают в личном чате Telegram. Обычный текст по-прежнему относится к inbox; для обучения используйте явные команды.

| Команда | Поведение |
|---|---|
| `/learn <тема>` | Создаёт короткий урок с теорией и одним вопросом. При существующем незавершённом уроке показывает его тему и точку продолжения, сохраняя паузу. Тема — до 500 символов. |
| `/answer <ответ>` | Сохраняет ответ и оценку AI, завершая активный урок. Ответ — до 3000 символов. На паузе отклоняется. |
| `/learn_ask <вопрос>` | Отвечает на уточнение или отступление, затем возвращает исходный учебный вопрос. Запрос — до 1000 символов. |
| `/learn_explain` | Даёт альтернативное объяснение текущего материала и возвращает исходный вопрос. |
| `/learn_pause` | Приостанавливает урок. Ответы и уточнения до возобновления отклоняются. |
| `/learn_resume` | Снимает паузу и показывает тему, вопрос и ожидаемое действие. В уже активном уроке просто повторяет точку продолжения без вызова LLM. |
| `/learn_finish` | Завершает активный или приостановленный урок без оценки. Позволяет начать другую тему; не создаёт свидетельства знания. |
| `/learn_request <запрос> \| <опыт>` | Создаёт программу из произвольного учебного запроса. Опыт обязателен как краткое самоописание; можно написать «не знаю». |
| `/learn_program <цель> \| <опыт>` | Явное планирование программы. Цель — 1–500 символов, опыт — 1–1000. |
| `/learn_project <id> \| <опыт>` | Создаёт программу по названию существующего проекта пользователя и сохраняет связь с ним. Проект и его задачи не изменяются. |
| `/learn_programs [page]` | Показывает собственные программы по 10 на страницу с командами выбора. |
| `/learn_select <id программы>` | Выбирает программу для диагностики, маршрута, следующего урока и подтверждения связей. |
| `/learn_link <код темы> \| <id навыка> \| <основание>` | Явно подтверждает, что тема выбранной программы проверяет именно этот существующий навык. Основание — 1–500 символов. Сначала завершите диагностику; существующую другую идентичность темы заменить нельзя. |
| `/learn_links` | Показывает подтверждённые связи текущего маршрута, источник, уровень доверия, время UTC и основания. |
| `/learn_diagnose <ответ>` | Отвечает на единственный необязательный диагностический вопрос; сохраняет исходный ответ и новую версию маршрута. Ответ — до 3000 символов. |
| `/learn_diagnose skip` | Пропускает диагностику и оставляет исходный маршрут без новой версии и без оценки знаний. |
| `/learn_route` | Показывает цель, дисциплину, текущую версию, причину её создания, темы и prerequisite; восстанавливает ожидаемый диагностический вопрос. |
| `/learn_next` | Начинает следующую доступную тему программы или показывает существующий незавершённый урок. Пока диагностика не завершена/пропущена, показывает вопрос и способ пропуска. |
| `/learn_adapt` | Запрашивает педагогическое предложение для следующей темы по текущим свидетельствам. Начинает адаптированный урок и сохраняет версию маршрута с причиной. При активном уроке показывает его точку продолжения. |
| `/learn_focus <код темы>` | Выбирает известную тему из `/learn_route`, в том числе для повторной практики; все её prerequisite должны быть пройдены. Сохраняет версию и причину ручного выбора. Сначала завершите активный урок через `/learn_finish`. |
| `/learn_skills [page]` | Показывает навыки по 10 на страницу с устойчивыми идентификаторами, командами статуса/практики и навигацией. Без номера открывается первая страница. |
| `/learn_status <id>` | Показывает статус, правила оценки, число положительных/отрицательных AI-оценок и последние три свидетельства с исходными ответами, основаниями и источником. |
| `/learn_practice <id>` | Создаёт новый короткий урок для выбранного собственного навыка. При незавершённом уроке возвращает его точку продолжения. |
| `/learn_reviews [page]` | Показывает наступившие повторения по 10 на страницу, сначала самое раннее, с командами начала, переноса и пропуска. |
| `/learn_review <id>` | Начинает новое задание на применение прежнего навыка, если наступил его срок. Существующий урок/пауза сохраняется. Ответ — через `/answer`. |
| `/learn_review_later <id>` | Переносит наступившее повторение на сутки от текущего времени. |
| `/learn_review_skip <id>` | Пропускает текущий срок и назначает следующий через 7 суток, без оценки знаний и штрафа. |

Пример: `/learn алгебра` → `/learn_ask Где это применяется в физике?` → `/learn_explain` → `/learn_pause` → перезапуск приложения → `/learn_resume` → `/answer ...`. Для выхода без ответа используйте `/learn_finish`.

Диагностика сохраняет дисциплину программы. Если планировщик предлагает другую дисциплину, ответ отклоняется без изменения маршрута и ожидающего вопроса. Генератор урока получает структурированный контекст: дисциплину, цель, исходный опыт и диагностические вопрос и ответ при их наличии. Эти данные считаются предварительными свидетельствами, а не подтверждением знаний.

Программа: `/learn_program освоить TypeScript | знаю JavaScript` → при необходимости `/learn_diagnose <ответ>` или `/learn_diagnose skip` → `/learn_route` → `/learn_next` → `/answer ...` → `/learn_next`. Если исходного опыта достаточно для выбора начала, LLM может сразу предложить маршрут без проверочного вопроса. Программа ограничена 12 темами; циклы, повторяющиеся коды, неизвестные или повторяющиеся зависимости, пустой/слишком длинный материал отклоняются до изменения состояния. Порядок тем нормализуется по зависимостям с сохранением предложенного порядка среди доступных тем.

Поддерживается несколько программ пользователя; каждая команда создания с новым Telegram update создаёт и выбирает новую программу, даже при совпадении цели. Повтор того же update не создаёт копию. `/learn_programs` показывает список, `/learn_select <id>` меняет контекст, `/learn_route` показывает ID выбранной программы. Выбор сохраняется после перезапуска. Перед созданием или выбором другой программы нужно ответить на текущий урок либо завершить его через `/learn_finish`; это относится и к паузе. Выбор уже текущей программы разрешён и не меняет урок. Сохраняется один незавершённый урок пользователя, поэтому `/answer` всегда имеет однозначный адресат. `/learn` сохраняет прежний сценарий отдельного урока. Свободный учебный запрос вводится через `/learn_request`, поскольку обычный текст занят существующим inbox. Автоматическое распознавание учебного намерения в обычном тексте пока не реализовано. Пауза и завершение относятся к уроку; отдельное управление жизненным циклом программы и изменение приоритета пока не доступны.

Следующая тема выбирается детерминированно: первый ещё не пройденный узел, все prerequisite которого пройдены. Для продвижения учитывается завершённый урок **этой программы и совместимой версии маршрута** с `IsCorrect=true`. Адаптивные версии сохраняют идентичность тем и прогресс; диагностическая перестройка начинает отдельную группу версий. Неверный ответ или выход без оценки оставляют тему для повторной попытки. Успешный ответ — лишь условие продвижения по маршруту, не подтверждение долговременного освоения; модель знаний оценивает свидетельства отдельно. После прохождения всех тем команда сообщает об окончании вопросов маршрута. Самооценка опыта и диагностический ответ не считаются абсолютной истиной; они хранятся отдельно от предложенного LLM маршрута.

Хранение программы: `learning_programs` содержит владельца, неизменную цель, дисциплину, исходный опыт, приоритет (пока фиксированный `1`), опциональный проект и состояние диагностики. `learning_routes` хранит отдельные версии с причинами и структурированным JSONB-массивом тем (`Code`, `Title`, `Prerequisites`), а не текстовым планом. Версия 1 основана на самоописании; диагностический ответ создаёт версию 2 с сохранением версии 1. Повторный диагностический вопрос после ответа отклоняется. Урок хранит `ProgramId`, `RouteVersion`, `TopicCode`; составные внешние ключи защищают владельца и ссылку на версию. Изоляция и транзакционная фиксация update/состояния/outbox действуют и для программ. Миграция `20261105172909_AddLearningPrograms` добавляет программу, версии и nullable-ссылки у уроков, сохраняя старые уроки. Её откат удаляет программы и связи, сохраняя содержимое уроков.

Состояния: `AwaitingAnswer` → `Paused` → `AwaitingAnswer`; из активного урока ответ переводит его в `Completed`; `/learn_finish` из активного урока или паузы переводит в `Finished`. Завершённый урок неизменяем, возобновление не создаёт новый урок. Одновременно у пользователя может быть один активный или приостановленный урок. Другой пользователь не получает к нему доступ. Материал генерируется на языке темы; оценка AI не является подтверждением освоения навыка.

Примените миграции `202611050001_AddLearningLessons`, `20261105164833_AddLessonDialogue` и `20261105171329_RemoveLessonContextSummary` обычным механизмом миграций приложения. Вторая миграция переносит старые уроки в корректные состояния и заполняет контекст, сохраняя ответы и оценки. Третья удаляет дублирующий текст `ContextSummary`: точка продолжения восстанавливается из существующих полей темы, вопроса и состояния. При откате третьей миграции текст пересоздаётся из этих полей. Уникальный индекс учитывает и активный урок, и паузу. Откат к старой схеме может быть отклонён её уникальным индексом, если у пользователя накопились несколько уроков, завершённых без ответа; автоматического удаления таких данных нет.

Поля `learning_lessons.Topic`, `Question` и `Status` — краткая детерминированная точка продолжения: тема, исходный вопрос и состояние, определяющее ожидаемое действие. Они хранятся независимо от истории уточнений в `learning_interactions` (запрос, вид объяснения, ответ; порядок — по `Id`). Domain контролирует переходы состояний; Telegram presenter формирует пользовательский текст из структурированного результата Application. Уточнения не меняют исходный вопрос или ожидаемый тип ответа. LLM получает тему, теорию, вопрос и состояние текущего шага, без воспроизведения растущего transcript; произвольные ссылки вроде «поясни второй пример из прошлого ответа» пока не разрешаются по истории. Возобновление читает PostgreSQL и не требует LLM.

Урок, история уточнения, обработанный update и исходящие сообщения фиксируются одной транзакцией; PostgreSQL advisory lock сериализует операции пользователя. Повторная доставка update после фиксации не вызывает LLM и не создаёт историю или сообщения повторно. При откате вызов LLM может повториться. Пустое, слишком длинное объяснение, ошибка провайдера и отмена запроса не меняют учебный шаг или историю. Теория и объяснения разбиваются на отдельные сообщения вместе с указанием следующего действия, каждое укладывается в лимит Telegram.

Доставка использует существующий outbox: временные ошибки повторяются после перезапуска с сохранением порядка чата. Постоянные ошибки Telegram отмечаются как `Failed`. Восстановить приглашение ответить можно новым `/learn_resume`. Доставка остаётся at-least-once: если Telegram принял сообщение перед сбоем записи результата, возможен повтор отправки.

Используются существующие `InboxAnalysis:OpenAI:Enabled`, `ApiKey`, `Model`, `MaxOutputTokens`, `TimeoutSeconds`. Ключ задаётся через runtime configuration. Невалидный материал и ошибка провайдера не создают урок и не завершают текущий; повторите команду новым сообщением.

Ограничения: генерация урока, планирование программы и адаптация выполняются внутри webhook и удерживают транзакцию до ответа LLM с ограничением времени каждого вызова. Адаптация требует двух последовательных вызовов: предложение и материал. Устойчивая фоновая генерация для длительных диалогов пока отсутствует. Учебные вызовы не включены в ledger стоимости inbox; длительность, модель и расход токенов успешных вызовов записываются в Serilog без содержимого и ключей, денежная стоимость не вычисляется. Проектные рекомендации и отчёты о применимости остаются следующими этапами. Управляющие сообщения пока на английском. Реальный OpenAI в проверках не вызывается; используются recording fakes и HTTP transport fake. При слишком малом `MaxOutputTokens` структурированный маршрут может не поместиться в ответ: усечённый ответ отклоняется, частичная программа не сохраняется.

## Свидетельства и статус навыка

`Skill` принадлежит пользователю и имеет собственный GUID, название и описание, независимо от программы. Для темы программы описание сохраняет дисциплину и учебную цель: повторная практика темы «Основы» получает предметный контекст. Повторные попытки одной темы в совместимых версиях маршрута используют тот же навык. Новый свободный `/learn <тема>` создаёт новую идентичность, даже при совпадении названия; для накопления свидетельств по прежнему навыку используйте `/learn_practice <id>`. Автоматического слияния по названиям нет. Межпрограммное переиспользование требует явного `/learn_link`, как описано ниже. Совместимость адаптивных версий задаётся явно через `ProgressVersion`, а не определяется похожими названиями или совпадением кодов после диагностики. Старые уроки без навыка при первом новом ответе получают описание из своей сохранённой темы.

После `/answer` сохраняется неизменяемое `LearningEvidence`: владелец, навык, идентификатор урока/операции, время UTC, исходный ответ, отдельная AI-интерпретация правильности и текст основания. Контекст вопроса и программы доступен через связанный урок. Метод — AI-оценка ответа; OpenAI adapter записывает фактическую модель из метаданных ответа провайдера, а не из сгенерированного текста. Другие адаптеры могут явно обозначить источник; отсутствие конкретной модели отображается как `LLM (unspecified model)`.

Ключ свидетельства — ID урока: один урок допускает один ответ и одно свидетельство. Навык, ответ, свидетельство, обработанный Telegram update и исходящие сообщения фиксируются существующей общей транзакцией. Повторы, пауза, выход без ответа и неуспешная оценка не увеличивают число свидетельств. Самоописание опыта и диагностическая интерпретация маршрута не дают mastery отдельных навыков: они остаются отдельно в программе.

`LearnerSkillState` вычисляется детерминированно из всех уникальных свидетельств, без изменяемого кеша или процентов знаний:

| Статус | Правило |
|---|---|
| `Unknown` | Нет оценённых ответов. |
| `NeedsPractice` | Есть отрицательные AI-оценки и нет положительных. |
| `Developing` | Один или два отдельных урока оценены положительно, отрицательных оценок нет. |
| `Demonstrated` | Не менее трёх отдельных уроков оценены положительно, отрицательных оценок нет. |
| `Conflicting` | Есть и положительные, и отрицательные оценки, независимо от порядка. |

Уверенность всегда предварительная: только AI-свидетельства. Даже `Demonstrated` не означает долговременного освоения. Две отрицательные оценки отмечают повторяющееся затруднение; тексты возможных причин сохраняются как гипотезы AI, без объявления подтверждённой одинаковой ошибки. Противоречия пока не снимаются автоматически последующими успехами; дополнительная независимая проверка остаётся следующим этапам. Правила сроков повторений описаны ниже. Статус учитывает все свидетельства, отчёт показывает последние три, каждое наблюдение и интерпретация идут отдельными сообщениями в пределах лимита Telegram.

Миграция `20261105191515_AddLearnerKnowledge` добавляет `learning_skills`, `learning_evidence` и nullable `learning_lessons.SkillId`. Составные внешние ключи защищают владельца навыка и урока. Старые уроки сохраняются без вымышленных свидетельств и дат; при новом ответе на старый незавершённый урок создаётся навык и реальное свидетельство. Откат удаляет новые навыки, свидетельства и ссылки, сохраняя исходные уроки, ответы и обратную связь. Последующее обновление не реконструирует удалённые свидетельства.

## Несколько программ и общий профиль

Пример: пройдите тему `basics` программы алгебры → найдите её ID навыка через `/learn_skills` → создайте программу физики → завершите/пропустите диагностику → `/learn_link basics | <id навыка алгебры> | Эта тема проверяет тот же алгебраический навык` → `/learn_next`. Связь подтверждает точную идентичность понятия, а не просто сходство названий. По умолчанию каждая новая тема имеет собственную идентичность. Чужой/неизвестный навык, неизвестная тема, незавершённая диагностика и неверное основание отклоняются. Когда тема уже связана с другим навыком через урок или подтверждение, замена запрещена: существующие свидетельства не переписываются. Повтор подтверждения того же навыка сохраняет первоначальное основание и время.

Общий профиль — существующие `learning_skills`, `learning_evidence` и `learning_reviews` пользователя. `ProgramSkillLink` связывает тему с каноническим навыком, сохраняя владельца, программу, корень совместимых версий маршрута, код темы, ID навыка, время UTC и основание. Источник — `User confirmation`, доверие — `UserConfirmedIdentity`: это пользовательское подтверждение идентичности, не независимая проверка содержания или mastery. LLM не создаёт связи и не выбирает ID. Отдельный каталог глобальных понятий и автоматическое семантическое сопоставление не вводились.

Перенос ограничен тем же навыком: следующий урок получает прежнее описание и предварительное состояние знаний вместе с целью/дисциплиной новой программы, адаптация учитывает прежние затруднения. Новые ответы пополняют те же свидетельства и единственное расписание повторения. Сама связь не создаёт свидетельство, не повышает mastery, не переносит прохождение тем и не обходит prerequisite. Противоречивые оценки остаются `Conflicting` во всех использующих навык программах. Прогресс и история маршрута вычисляются только по урокам конкретной программы. Адаптивные версии наследуют связь через `ProgressVersion`; диагностическая перестройка начинает другую группу и не получает связи автоматически. Частичная аналогия разных навыков, автоматическое объединение уже накопленных идентичностей, отзыв подтверждения и комбинированные междисциплинарные упражнения не реализованы; последние остаются M11.

Миграция `20261106143915_AddMultipleLearningPrograms` снимает уникальность программы по пользователю, добавляет `learning_contexts` и `learning_program_skill_links`. Прежняя единственная программа автоматически остаётся выбранной; уроки, маршруты, навыки, свидетельства и сроки не изменяются. Составные FK защищают владельца программы и навыка, FK маршрута — существование версии. Выбор, подтверждение, processed update и outbox фиксируются общей транзакцией с прежней блокировкой пользователя. Откат удаляет выбор и подтверждения, сохраняя программы и свидетельства; повторное обновление при одной программе снова выбирает её, но не восстанавливает удалённые подтверждения. При нескольких программах владельца откат атомарно отклоняется старым уникальным индексом: миграция ничего не удаляет для его удовлетворения. Перед downgrade оператор должен отдельно решить, как сохранить и сократить эти данные.

## Адаптивный преподаватель

`/learn_next` проверяет модель знаний следующей доступной темы. Если по её навыку накопились две отрицательные AI-оценки, система запрашивает коррекцию, а не повторяет обычную генерацию. `/learn_adapt` позволяет запросить адаптацию раньше. Лимит контекста: состояние навыка и последние три основания AI-оценок, каждое до 500 символов; полный transcript не передаётся. Количество отрицательных оценок означает повторяющееся затруднение, а не доказанную одинаковую причину ошибки.

LLM предлагает только `Action`, `TopicCode`, `Reason` (до 250 символов). Application проверяет каталог действий и доступность цели:

| Действие | Поведение |
|---|---|
| `Hint` | Новый вопрос по текущей теме со scaffold-подсказкой без готового ответа. |
| `Explain` | Другое объяснение и пример по текущей теме. |
| `Simplify` | Меньшая сложность и конкретный пример. |
| `Practice` | Другой вопрос текущего уровня. |
| `ReviewPrerequisite` | Возврат к непосредственному или транзитивному prerequisite; его собственные зависимости должны быть пройдены. |
| `Advance` | Следующая доступная тема; запрещено при `NeedsPractice`, `Conflicting` или повторяющемся затруднении текущего навыка. |

При успешной проверке генератор получает выбранное действие, контекст программы и свидетельства. Причина версии содержит исходную/выбранную тему, число положительных и отрицательных оценок и отдельное предварительное основание AI. Материал проверяется до применения версии. Неизвестное действие, чужой/неизвестный код, обход зависимостей, неверное основание, отказ/невалидный материал и отмена не применяют версию или новый урок. Существующий активный или приостановленный урок сохраняется; для смены направления сначала используйте `/learn_finish`.

Перестройка ограничена приоритетом известных тем и возвратом к prerequisite. Domain сохраняет все темы, их названия и зависимости, цель, дисциплину и предыдущие версии. `/learn_focus <код>` задаёт приоритет явно, без запроса предложения LLM, но с генерацией материала. Адаптация не добавляет произвольные темы, не удаляет зависимости, не пропускает непроверенные темы и не повышает mastery сама по себе. Успешный ответ позволяет двигаться дальше по прежнему правилу прогресса; `Conflicting` при этом не переименовывается в подтверждённое освоение.

Миграция `20261106114130_AddAdaptiveTeaching` добавляет nullable `learning_routes.ProgressVersion`: корневую версию с общей идентичностью тем. У исходных и диагностических маршрутов `null` означает собственную версию. Адаптация наследует корень; уроки и навыки находят прежний прогресс в этой группе, без переноса между программами или диагностическими перестройками. Версия, урок, update и outbox фиксируются общей транзакцией. Повтор update не вызывает адаптацию повторно. Откат миграции сохраняет версии, причины, уроки и свидетельства, но удаляет связь совместимости; повторное обновление не восстанавливает её автоматически, поэтому после downgrade адаптивные версии снова считаются отдельными группами прогресса.

## Интервальные повторения

После оценённого ответа существует ровно одна запись `learning_reviews` на навык. Запрос `/learn_reviews` читает наступившие сроки, не создавая задания или уведомления. Сортировка — срок UTC, затем идентификатор навыка. Доступ ограничен владельцем. Просрочка любой длительности остаётся одной записью; новый срок считается от фактического ответа, без очереди «догоняющих» повторений.

| Событие | Следующий срок |
|---|---|
| Первый ответ с положительной AI-оценкой | Через 24 часа |
| Любой ответ с отрицательной AI-оценкой | Через 1 час, счётчик успешных повторений сбрасывается |
| Первое успешное наступившее повторение | Через 3 суток |
| Второе, третье, четвёртое и последующие успешные повторения | Через 7, 14, 30, далее 30 суток |
| Положительная обычная практика | Существующий срок сохраняется, счётчик повторений не увеличивается |
| Перенос / пропуск | Через 1 / 7 суток от команды, без свидетельства или изменения счётчика |

Все интервалы — длительности в UTC. Счётчик успешных наступивших повторений ограничен четырьмя — этого достаточно для выбора максимального интервала. Досрочная практика не доказывает удержание знаний и не позволяет постоянно отодвигать повторение. `/learn_review` доступна только при наступившем сроке; для досрочной практики есть `/learn_practice`. Перенос и пропуск доступны только для наступившего срока, когда нет активного/приостановленного урока по этому навыку. Повторные команды до нового срока не отодвигают его ещё раз. `/learn_finish` оставляет срок без изменения.

Пример: `/learn_next` → `/answer ...` → через сутки `/learn_reviews` → `/learn_review <id>` → `/answer ...` → `/learn_status <id>`. Генератор получает прежнее описание навыка и `IsReview=true`: требуется новая ситуация применения и вопрос на воспроизведение, без готового ответа в теории. Application связывает задание с точным прежним `SkillId`; LLM не выбирает идентичность навыка. Проверяется один старый навык в новом задании; комбинированные междисциплинарные задания не входят в этот срез. Повторение не продвигает маршрут программы само по себе. Качество и новизна содержания зависят от LLM, а не проверяются независимым валидатором.

Ответ повторения сохраняется как новое неизменяемое `LearningEvidence` с `IsReview`, исходным ответом, навыком, временем, уроком и происхождением AI-оценки. Он участвует в прежних правилах `LearnerSkillState`: меняет числа оценок и, когда выполнены условия, категорию mastery. Отрицательный результат после положительного даёт `Conflicting`; последующие успехи не стирают противоречия. Даже успешные отложенные AI-проверки не объявляются доказанным долговременным освоением. `/learn_status` показывает следующий срок и счётчик повторений. Ошибка/невалидный ответ LLM, пауза и завершение без ответа не создают свидетельство и не меняют срок.

Миграция `20261106122410_AddSpacedReviews` добавляет `learning_reviews` и признаки `IsReview` у уроков/свидетельств. Для существующего навыка со свидетельствами первый срок строится от последней по времени оценки: сутки при положительной, час при отрицательной; при одинаковом времени порядок задаёт GUID урока. Успешные повторения задним числом не выдумываются. Навык без оценок ещё не получает срок. Откат сохраняет навыки, уроки, исходные ответы, оценки и outbox, но удаляет расписание и признаки повторения; повторное обновление восстанавливает только начальные сроки по последним оценкам со счётчиком 0.

Изменение срока, урок/свидетельство, processed update и исходящий ответ сохраняются в существующей общей транзакции с блокировкой пользователя. Повтор update не создаёт повторного эффекта; новый update при активном уроке возвращает существующий шаг. PostgreSQL хранит состояние между перезапусками, outbox сохраняет ожидающий доставки ответ. Фоновые приглашения описаны ниже. Сохраняются ограничения синхронной генерации в webhook, AI-оценки, отсутствия учебного ledger и at-least-once доставки.

## Расписание и приглашения

Уведомления включаются только после явной настройки. Частота и окна общие для пользователя, независимо от числа программ. Пример: `/learn_schedule Europe/Moscow | 1 | 09:00-10:00,18:00-20:00`. Укажите известный системе часовой пояс (предпочтительно IANA), интервал от 1 до 30 календарных дней и от одного до четырёх непересекающихся ежедневных окон `HH:mm-HH:mm`. Начало включено, конец исключён; конец должен быть позже начала в тех же сутках. Ночное время задаётся отдельными окнами по разные стороны полуночи, например `00:00-02:00,22:00-23:59`; `24:00` не поддерживается. Дни недели, отдельная частота для программ и приоритеты программ не настраиваются.

| Команда | Поведение |
|---|---|
| `/learn_schedule` | Показывает частоту, местные окна, часовой пояс, паузу и следующий допустимый срок UTC. Этот срок не гарантирует наличие учебного материала или точное время доставки. |
| `/learn_schedule <пояс> \| <интервал дней> \| <окна>` | Сохраняет настройки; отзывает прежнее приглашение. Не снимает включённую паузу. |
| `/learn_notify_pause` | Отключает приглашения до явного возобновления; не приостанавливает текущий урок. |
| `/learn_notify_resume` | Возобновляет уведомления с учётом текущего времени и частоты, без очереди за пропущенные дни. |
| `/learn_invite_start <id>` | Принимает конкретное приглашение: начинает наступившее повторение или выбирает указанную в нём программу и запускает следующий урок. Если пользователь уже начал другой урок, возобновляет его. Ошибка LLM оставляет приглашение для явной повторной попытки. |
| `/learn_invite_later <id>` | Однократно откладывает следующее приглашение минимум на час, до разрешённого окна; выбор материала выполняется заново при наступлении срока. |
| `/learn_invite_skip <id>` | Однократно закрывает приглашение, сохраняя очередной обычный срок расписания. |

В приглашении есть полные текстовые команды «начать / позже / пропустить» с ID, кнопки не требуются. ID проверяется вместе с владельцем. Чужое, отозванное, уже использованное или истёкшее приглашение не создаёт урок. Приглашение действительно до следующего срока расписания; с новым сроком старый ID теряет силу. Начать вручную через `/learn_next` или `/learn_reviews` можно всегда по прежним правилам, в том числе вне временных окон и при паузе уведомлений.

Первое приглашение возможно сразу внутри разрешённого окна; вне окна планируется ближайшее. После фактического создания приглашения очередной срок — первый момент окна через заданное число **местных календарных дней** от его даты. Смена часового пояса пересчитывает срок в новом поясе от времени последнего приглашения, сохраняя ограничение частоты. При DST отсутствующее время сдвигается вперёд до первого допустимого момента в этом окне; если всё окно попало в пропуск, выбирается следующее. Из двух неоднозначных моментов выбирается ближайший подходящий UTC; повторного приглашения во второй час нет.

Просроченные повторения имеют приоритет: выбирается один самый ранний срок, затем ID навыка. Иначе приглашается следующий доступный урок выбранной программы, если диагностика закончена. При активном/приостановленном уроке или отсутствии материала приглашение не создаётся; внутри окна планировщик переходит к следующей дате частоты. При задержке за пределы окна выбирается ближайшее будущее окно. После длительного простоя внутри окна создаётся максимум одно актуальное приглашение; задачи за пропущенные дни не накапливаются. Пользовательский перенос может дать дополнительное приглашение в тот же день. Пропуск и перенос **приглашения** не меняют `ReviewSchedule`, свидетельства, освоение, прохождение тем, задачи, проекты или Commitment. Явные команды `/learn_review_later` и `/learn_review_skip` по-прежнему меняют только срок самого повторения.

`StudyInvitationWorker` проверяет PostgreSQL каждые 30 секунд, партиями до 50 пользователей. Сохраняемая `learning_study_schedules.NextAt` служит устойчивым заданием; отдельного scheduler в исходном коде не было. Изменение расписания и помещение приглашения в существующий Telegram outbox выполняются одной транзакцией с той же advisory-блокировкой пользователя, что и webhook. Несколько обработчиков повторно проверяют срок после блокировки, поэтому не создают дубликаты. Фоновый процесс не вызывает LLM. Специальных параметров конфигурации и новых пакетов нет; до запуска обновлённого Host нужно применить миграцию.

Перед доставкой приглашения outbox получает ту же блокировку и повторно проверяет ID, паузу, текущее окно, отсутствие активного урока и наступивший срок приглашённого повторения. Задержавшиеся за пределы окна, отозванные и устаревшие приглашения помечаются `Failed` с `StudyInvitationSuppressed`, без отправки; следующее приглашение создаст обычный цикл расписания. Временный отказ Telegram внутри окна повторяется существующим механизмом outbox после перезапуска; конкурирующий обработчик повторно проверяет время следующей попытки, сохраняя backoff. Порядок сообщений чата сохраняется; предыдущие ожидающие сообщения могут задержать приглашение. Транзакционная запись устраняет дубликаты планирования, но доставка остаётся **at-least-once**: после приёма Telegram и сбоя фиксации `Sent` возможна повторная отправка. Живые Telegram/OpenAI не входят в автоматические проверки.

Миграция `20261106152635_AddStudySchedules` добавляет `learning_study_schedules` и nullable `telegram_outbox_messages.study_invitation_id`. Первичный ключ ограничивает расписание одной записью на пользователя, составные внешние ключи защищают владельца целевой программы/навыка; constraints проверяют частоту и единственную цель приглашения. Старые уроки, программы, повторения и сообщения сохраняются; расписания не создаются без согласия. Откат удаляет настройки и ID, сохраняя учебные данные и историю outbox; ожидающие приглашения переводятся в `Failed` с `StudyScheduleRemoved`, чтобы старый Host не отправил их без проверки актуальности. Повторное обновление не восстанавливает удалённые настройки.
