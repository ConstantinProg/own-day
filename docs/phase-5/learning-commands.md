# Урок и продолжение диалога

Команды работают в личном чате Telegram. Обычный текст по-прежнему относится к inbox; для обучения используйте явные команды.

| Команда | Поведение |
|---|---|
| `/learn <тема>` | Создаёт короткий урок с теорией и одним вопросом. При существующем незавершённом уроке показывает его тему и точку продолжения, сохраняя паузу. Тема — до 500 символов. |
| `/answer <ответ>` | Сохраняет ответ и оценку AI, завершая активный урок. Ответ — до 3000 символов. На паузе отклоняется. |
| `/learn_ask <вопрос>` | Отвечает на уточнение или отступление, затем возвращает исходный учебный вопрос. Запрос — до 1000 символов. |
| `/learn_explain` | Даёт альтернативное объяснение текущего материала и возвращает исходный вопрос. |
| `/learn_pause` | Приостанавливает урок. Ответы и уточнения до возобновления отклоняются. |
| `/learn_resume` | Снимает паузу и показывает тему, вопрос и ожидаемое действие. В уже активном уроке просто повторяет точку продолжения без вызова LLM. |
| `/learn_finish` | Завершает активный или приостановленный урок без оценки. Позволяет начать другую тему; не создаёт свидетельства знания. |

Пример: `/learn алгебра` → `/learn_ask Где это применяется в физике?` → `/learn_explain` → `/learn_pause` → перезапуск приложения → `/learn_resume` → `/answer ...`. Для выхода без ответа используйте `/learn_finish`.

Состояния: `AwaitingAnswer` → `Paused` → `AwaitingAnswer`; из активного урока ответ переводит его в `Completed`; `/learn_finish` из активного урока или паузы переводит в `Finished`. Завершённый урок неизменяем, возобновление не создаёт новый урок. Одновременно у пользователя может быть один активный или приостановленный урок. Другой пользователь не получает к нему доступ. Материал генерируется на языке темы; оценка AI не является подтверждением освоения навыка.

Примените миграции `202611050001_AddLearningLessons`, `20261105164833_AddLessonDialogue` и `20261105171329_RemoveLessonContextSummary` обычным механизмом миграций приложения. Вторая миграция переносит старые уроки в корректные состояния и заполняет контекст, сохраняя ответы и оценки. Третья удаляет дублирующий текст `ContextSummary`: точка продолжения восстанавливается из существующих полей темы, вопроса и состояния. При откате третьей миграции текст пересоздаётся из этих полей. Уникальный индекс учитывает и активный урок, и паузу. Откат к старой схеме может быть отклонён её уникальным индексом, если у пользователя накопились несколько уроков, завершённых без ответа; автоматического удаления таких данных нет.

Поля `learning_lessons.Topic`, `Question` и `Status` — краткая детерминированная точка продолжения: тема, исходный вопрос и состояние, определяющее ожидаемое действие. Они хранятся независимо от истории уточнений в `learning_interactions` (запрос, вид объяснения, ответ; порядок — по `Id`). Domain контролирует переходы состояний; Telegram presenter формирует пользовательский текст из структурированного результата Application. Уточнения не меняют исходный вопрос или ожидаемый тип ответа. LLM получает тему, теорию, вопрос и состояние текущего шага, без воспроизведения растущего transcript; произвольные ссылки вроде «поясни второй пример из прошлого ответа» пока не разрешаются по истории. Возобновление читает PostgreSQL и не требует LLM.

Урок, история уточнения, обработанный update и исходящие сообщения фиксируются одной транзакцией; PostgreSQL advisory lock сериализует операции пользователя. Повторная доставка update после фиксации не вызывает LLM и не создаёт историю или сообщения повторно. При откате вызов LLM может повториться. Пустое, слишком длинное объяснение, ошибка провайдера и отмена запроса не меняют учебный шаг или историю. Теория и объяснения разбиваются на отдельные сообщения вместе с указанием следующего действия, каждое укладывается в лимит Telegram.

Доставка использует существующий outbox: временные ошибки повторяются после перезапуска с сохранением порядка чата. Постоянные ошибки Telegram отмечаются как `Failed`. Восстановить приглашение ответить можно новым `/learn_resume`. Доставка остаётся at-least-once: если Telegram принял сообщение перед сбоем записи результата, возможен повтор отправки.

Используются существующие `InboxAnalysis:OpenAI:Enabled`, `ApiKey`, `Model`, `MaxOutputTokens`, `TimeoutSeconds`. Ключ задаётся через runtime configuration. Невалидный материал и ошибка провайдера не создают урок и не завершают текущий; повторите команду новым сообщением.

Ограничения: генерация по-прежнему выполняется внутри webhook и удерживает транзакцию до ответа LLM с ограничением времени. Устойчивая фоновая генерация для длительных диалогов пока отсутствует. Учебные вызовы не включены в ledger стоимости inbox; длительность, модель и расход токенов успешных вызовов записываются в Serilog без содержимого и ключей, денежная стоимость не вычисляется. Программа и модель знаний относятся к следующим этапам. Управляющие сообщения пока на английском. Реальный OpenAI в проверках диалога не вызывается; используются recording fakes и HTTP transport fake.
