## 0. Инструкция Codex

Работай последовательно, **один milestone за один запрос/PR**. Перед началом:

1. Прочитай `AGENTS.md`, настоящее `plan.md`, `phase-5-requirements.md` и применимые документы в `docs/`.
2. Изучи **фактическую** реализацию, текущую ветку, миграции, тесты, Telegram pipeline, LLM abstraction, фоновые механизмы и доступные модели задач/проектов. Не считай предположения из ТЗ доказательством существования кода.
3. Если milestone уже реализован, представь доказательства и недостающие части; не дублируй функциональность.
4. Реализуй минимальный сквозной срез. Не добавляй код для будущих milestones, кроме неизбежных совместимых расширений.
5. Соблюдай Clean Architecture и существующие соглашения репозитория. Избегай ненужных новых проектов, пакетов, сервисов и абстракций.
6. Сохраняй PostgreSQL как authoritative state; LLM — источник предложений, не доверенный владелец состояния.
7. Обнови тесты, миграции, документацию и `plan.md`. Выполни доступные проверки. Не отмечай milestone завершённым при падающих обязательных тестах.
8. В отчёте укажи изменения, тесты и их результаты, известные ограничения, отклонения от ТЗ и следующий milestone. При архитектурной неопределённости остановись и предложи варианты, а не делай масштабный необратимый рефакторинг.

## 1. Этапы

### M1 — Первый работающий урок
**Статус:** DONE  
**Требования:** UC-01, UC-04 (базово), FR-02 (частично).

**Реализовать:** пользователь начинает обучение произвольной теме через Telegram; OwnDay генерирует краткую теорию, задаёт один вопрос, принимает ответ и выдаёт обратную связь; минимальное состояние занятия и результат сохраняются в PostgreSQL. Использовать существующую LLM-интеграцию или минимальный провайдерный порт. Обеспечить разграничение пользователей и обработку повторных updates.

**Приёмка:**
- [x] Полный Telegram → Application → LLM → Persistence → Telegram сценарий.
- [x] Урок и результат сохраняются и доступны после перезапуска.
- [x] Повторный update не дублирует состояние.
- [x] Проверены успешный ответ, ошибка LLM и некорректный ответ.
- [x] Unit + integration tests, миграция и описание команды.

**Не делать:** curriculum engine, граф навыков, scheduler, сложную аналитику.

**Проверка (2026-11-05):** реализованы `/learn <тема>` и `/answer <ответ>`, Lesson, Application orchestration, OpenAI adapter и миграция `202611050001_AddLearningLessons`. HTTP-тесты с fake LLM проверяют полный сценарий, изоляцию, повторы и невалидный материал; PostgreSQL-тест применяет миграции и читает урок и результат через новые DbContext. Проверены отмена, отказ оценки и соответствие snapshot модели. Release build: 0 warnings/errors; 448 unit и 335 integration tests прошли, 1 реальный OpenAI smoke test пропущен.

**Отклонения и риски по результатам M1:** вход только явными командами; LLM вызывается внутри webhook с удержанием транзакции. Для длительных диалогов требуется устойчивая фоновая генерация. Используются настройки OpenAI inbox, но учебные вызовы не входят в его бюджетный ledger. Логируются модель, latency и токены успешных вызовов без содержимого. Управляющие ответы пока на английском. На момент проверки M1 реальный OpenAI и полный перезапуск Host для нового сценария не проверены; долговечность проверена через новые подключения. См. [команды и ограничения](learning-commands.md).

**Приёмка:**
- [x] Программа хранится структурированно и переживает перезапуск.
- [x] Диагностика учитывает исходный опыт и избегает обязательного длинного теста.
- [x] Можно просмотреть маршрут и начать следующий урок.
- [x] Невалидные зависимости/предложения LLM отклоняются.

**Проверка (2026-11-05):** реализованы `/learn_request <запрос> | <опыт>`, `/learn_program <цель> | <опыт>`, `/learn_project <id> | <опыт>`, `/learn_diagnose <ответ|skip>`, `/learn_route`, `/learn_next`. В репозитории есть `Project` и проверка владельца через `StructuredItemService`, поэтому проектный вход реализован сейчас; рекомендации и отчёты о применимости остаются M10. `LearningProgram` хранит исходную цель, дисциплину, опыт, приоритет `1`, опциональный проект и состояние диагностики. `CurriculumRoute` хранит версии с причиной и структурированными темами/зависимостями в JSONB. LLM получает исходный опыт и может предложить один необязательный вопрос; ответ сохраняется отдельно от интерпретации, создаёт версию 2, не заменяя исходную цель и версию 1. Пропуск оставляет версию 1. Повторный вопрос после ответа отклоняется. Урок связан с программой, версией и кодом темы; продвижение требует корректного по AI ответа, не объявляя mastery. Неверный ответ и завершение без оценки оставляют тему для повторной попытки.

### M4 — Персональная модель знаний
**Статус:** DONE
**Требования:** UC-06, FR-03.

**Реализовать:** общие идентичности навыков, LearningEvidence, learner skill state, происхождение и основания оценок, повторяющиеся ошибки; явные правила обновления mastery. Не использовать «процент знаний» без определённой семантики.

**Приёмка:**
- [x] Различаются наблюдения и выводы LLM.
- [x] Два одинаковых события не учитываются дважды.
- [x] Противоречивые результаты не дают ложной полной уверенности.
- [x] Есть пользовательский запрос статуса навыка и объяснение оценки.
- [x] Детерминированные тесты алгоритма и миграции.

**Проверка (2026-11-05):** добавлены `Skill`, неизменяемые `LearningEvidence` и вычисляемый `LearnerSkillState`. Идентичность навыка — собственный GUID с владельцем, названием и описанием, независимо от программы. Описание темы программы сохраняет дисциплину и цель для последующей практики. Повторные попытки темы одной версии маршрута используют прежний навык; новый свободный урок получает отдельную идентичность, без автоматического слияния по названиям. Команды `/learn_skills`, `/learn_status <id>`, `/learn_practice <id>` позволяют найти навык, увидеть основания оценки и накопить новые свидетельства. Отдельно сохраняются исходный ответ, время UTC, ссылка на урок/операцию, метод AI-проверки, её результат и текст основания; OpenAI adapter берёт фактическую модель из метаданных провайдера. Уникальный ключ свидетельства по уроку и существующая транзакция update/состояния/outbox предотвращают повторный учёт. Завершение без ответа и ошибки оценки не создают свидетельств.

**Правила mastery:** без свидетельств — `Unknown`; только отрицательные AI-оценки — `NeedsPractice`; один-два положительно оценённых урока без отрицательных — `Developing`; минимум три — `Demonstrated`; сочетание положительных и отрицательных — `Conflicting`, независимо от порядка. Все статусы предварительные и не доказывают долговременного освоения. Две отрицательные оценки отмечают повторяющееся затруднение; возможные причины из обратной связи остаются гипотезами AI. Проценты знаний и вероятности не используются. Состояние вычисляется из уникальных свидетельств, отдельный изменяемый кеш не вводится.

**Выполненные проверки:** `dotnet restore OwnDay.slnx --disable-parallel` — успешно; `dotnet build OwnDay.slnx --configuration Release --no-restore -m:1` — 0 warnings/errors; итоговый `dotnet test OwnDay.slnx --configuration Release --no-build -m:1` — 538 unit и 362 integration tests прошли, 1 реальный OpenAI smoke test пропущен. Использован изолированный PostgreSQL 18 в Docker с `OWNDAY_TEST_POSTGRES_CONNECTION` и `Pooling=false`. Проверены правила mastery, дубли, противоречия, происхождение оценки, отмена и невалидный результат провайдера без мутации, изоляция пользователей и максимальная длина сообщений Telegram. PostgreSQL-тест применяет миграцию `20261105191515_AddLearnerKnowledge` к старому уроку, пересоздаёт Host дважды, сохраняет свидетельства после повторного update и проверяет откат/повторное обновление с сохранением исходных уроков. EF snapshot сверён после исправления порядка объявлений: `dotnet-ef migrations has-pending-model-changes` — изменений нет. `git diff --check` и проверка новых файлов на хвостовые пробелы — без ошибок. Архитектурный review локальным навыком не выявил оставшихся нарушений направления зависимостей, границ владельца и атомарности.

**Ограничения и отклонения:** поддержан один вид свидетельства — AI-оценка ответа на вопрос, без детерминированной независимой проверки (M9). Диагностика и самоописание опыта остаются в программе и не присваивают mastery отдельным навыкам. Повторяющееся затруднение определяется числом отрицательных оценок, без семантического объединения ошибок. Противоречия автоматически не снимаются последующими успехами; уточнение правил и дополнительные проверки остаются следующим этапам. Сопоставление навыков между программами и версиями маршрута не автоматизировано (M5/M7). Старые уроки не получают вымышленных свидетельств задним числом; первый новый ответ создаёт навык с описанием из сохранённой темы. Откат удаляет новые навыки и свидетельства, сохраняя исходные уроки, ответы и feedback. Сохраняются явные команды, генерация в webhook с транзакцией, отсутствие учебного ledger/фоновой генерации, английские управляющие ответы и at-least-once доставка. Live OpenAI и Telegram не проверялись. Следующий этап — M5, адаптивный преподаватель; M5–M12 остаются TODO по правилу одного этапа на запрос. См. [команды, правила оценки и миграция](learning-commands.md).

Начало запускает нужное повторение или выбирает сохранённую программу и вызывает прежний use case следующего урока; уже начатый урок возобновляется. Ошибка/невалидный материал LLM оставляет приглашение для явного повтора. Перенос закрывает ID и назначает новое приглашение минимум через час в разрешённом окне с актуальным выбором материала; пропуск закрывает ID и сохраняет обычный срок. Ни одно действие приглашения не меняет учебные свидетельства, даты самого повторения, прохождение тем, задачи, проекты или Commitment. ID ограничен владельцем и действителен до следующего срока; повторные и чужие действия не создают эффектов.
