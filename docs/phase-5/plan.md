## 0. Инструкция Codex

Работай последовательно, **один milestone за один запрос/PR**. Перед началом:

1. Прочитай `AGENTS.md`, настоящее `plan.md`, `phase-5-requirements.md` и применимые документы в `docs/`.
2. Изучи **фактическую** реализацию, текущую ветку, миграции, тесты, Telegram pipeline, LLM abstraction, фоновые механизмы и доступные модели задач/проектов. Не считай предположения из ТЗ доказательством существования кода.
3. Если milestone уже реализован, представь доказательства и недостающие части; не дублируй функциональность.
4. Реализуй минимальный сквозной срез. Не добавляй код для будущих milestones, кроме неизбежных совместимых расширений.
5. Соблюдай Clean Architecture и существующие соглашения репозитория. Избегай ненужных новых проектов, пакетов, сервисов и абстракций.
6. Сохраняй PostgreSQL как authoritative state; LLM — источник предложений, не доверенный владелец состояния.
7. Обнови тесты, миграции, документацию и `plan.md`. Выполни доступные проверки. Не отмечай milestone завершённым при падающих обязательных тестах.
8. В отчёте укажи изменения, тесты и их результаты, известные ограничения, отклонения от ТЗ и следующий milestone. При архитектурной неопределённости остановись и предложи варианты, а не делай масштабный необратимый рефакторинг.

**Статусы:** `TODO`, `IN PROGRESS`, `DONE`, `BLOCKED`. Изменяй статус и критерии приёмки только после фактической проверки.

## 1. Этапы

### M1 — Первый работающий урок
**Статус:** DONE  
**Требования:** UC-01, UC-04 (базово), FR-02 (частично).

**Реализовать:** пользователь начинает обучение произвольной теме через Telegram; OwnDay генерирует краткую теорию, задаёт один вопрос, принимает ответ и выдаёт обратную связь; минимальное состояние занятия и результат сохраняются в PostgreSQL. Использовать существующую LLM-интеграцию или минимальный провайдерный порт. Обеспечить разграничение пользователей и обработку повторных updates.

**Приёмка:**
- [x] Полный Telegram → Application → LLM → Persistence → Telegram сценарий.
- [x] Урок и результат сохраняются и доступны после перезапуска.
- [x] Повторный update не дублирует состояние.
- [x] Проверены успешный ответ, ошибка LLM и некорректный ответ.
- [x] Unit + integration tests, миграция и описание команды.

**Не делать:** curriculum engine, граф навыков, scheduler, сложную аналитику.

**Проверка (2026-11-05):** реализованы `/learn <тема>` и `/answer <ответ>`, Lesson, Application orchestration, OpenAI adapter и миграция `202611050001_AddLearningLessons`. HTTP-тесты с fake LLM проверяют полный сценарий, изоляцию, повторы и невалидный материал; PostgreSQL-тест применяет миграции и читает урок и результат через новые DbContext. Проверены отмена, отказ оценки и соответствие snapshot модели. Release build: 0 warnings/errors; 448 unit и 335 integration tests прошли, 1 реальный OpenAI smoke test пропущен.

**Отклонения и риски по результатам M1:** вход только явными командами; LLM вызывается внутри webhook с удержанием транзакции. Для длительных диалогов требуется устойчивая фоновая генерация. Используются настройки OpenAI inbox, но учебные вызовы не входят в его бюджетный ledger. Логируются модель, latency и токены успешных вызовов без содержимого. Управляющие ответы пока на английском. На момент проверки M1 реальный OpenAI и полный перезапуск Host для нового сценария не проверены; долговечность проверена через новые подключения. См. [команды и ограничения](learning-commands.md).

### M2 — Продолжение и восстановление диалога
**Статус:** DONE
**Требования:** UC-04, UC-05, FR-02.

**Реализовать:** уточняющие вопросы, альтернативные объяснения, паузу, продолжение и завершение; явные состояния и переходы занятия; краткое восстановимое представление контекста отдельно от transcript; надёжность исходящих сообщений.

**Приёмка:**
- [x] Можно отклониться от темы и вернуться к учебному шагу.
- [x] После перезапуска восстанавливается ожидаемое действие.
- [x] Невалидные переходы отвергаются; повторы идемпотентны.
- [x] Тесты на прерывание, возобновление, завершение и сбои доставки.

**Проверка (2026-11-05):** добавлены `/learn_ask <вопрос>`, `/learn_explain`, `/learn_pause`, `/learn_resume`, `/learn_finish`; Domain контролирует состояния `AwaitingAnswer`, `Paused`, `Completed`, `Finished`. Восстановимый `ContextSummary` хранится отдельно от истории уточнений `learning_interactions`; пояснения не меняют исходный вопрос. Миграция `20261105164833_AddLessonDialogue` переносит старые уроки с сохранением ответов и заполняет контекст. HTTP-тесты проверяют отступления, альтернативное объяснение, паузу, отказ ответить на паузе, возобновление, завершение без оценки, новую тему, изоляцию и повторы. PostgreSQL-тест пересоздаёт Host дважды, восстанавливает ожидаемое действие и после временного отказа доставляет сохранённые сообщения через существующий outbox, без повторного вызова LLM. Отдельно проверены обновление старой базы с несколькими завершёнными уроками, отмена, невалидное объяснение, отказ провайдера, структура запроса OpenAI через fake HTTP и лимит сообщений Telegram.

**Выполненные проверки:** `dotnet restore OwnDay.slnx`; `dotnet build OwnDay.slnx --configuration Release --no-restore -m:1` — 0 warnings/errors; `dotnet test OwnDay.slnx --configuration Release --no-build -m:1` — 491 unit и 340 integration tests прошли, 1 реальный OpenAI smoke test пропущен. Для полного прогона использован временный PostgreSQL 18 с `OWNDAY_TEST_POSTGRES_CONNECTION` и `Pooling=false`: первый полный прогон с pooling исчерпал лимит соединений из-за отдельных пулов тестовых схем, повторный полный прогон прошёл. `dotnet-ef migrations has-pending-model-changes` — изменений нет; `git diff --check` — без ошибок. Архитектурные границы проверены локальным навыком review: новых нарушений направления зависимостей и транзакционных границ не найдено.

**Ограничения и риски для M3:** поддержан короткий диалог с одним проверочным вопросом. Контекст продолжения детерминированный, без воспроизведения всей истории; ссылки на детали прежних пояснений не разрешаются по transcript. Сохраняются ограничения M1: явные команды, генерация в webhook с транзакцией и timeout, отсутствие устойчивой фоновой генерации и учебного бюджетного ledger, управляющие сообщения на английском. Реальный провайдер и live Telegram для нового диалога не проверялись; перезапуски Host и повторная доставка проверены с fake LLM/Telegram на реальном PostgreSQL. Доставка остаётся at-least-once. Эти ограничения не снимают соответствующие требования всей фазы; до длительных диалогов требуется фоновая генерация. Следующий этап — M3, учебная программа и диагностика; M3–M12 остаются TODO по правилу одного этапа на запрос.

**Контрольная точка:** после M2 OwnDay уже пригоден для реальных коротких занятий.

## 2. Общий Definition of Done

Для каждого milestone:

- [ ] Есть доступный текстовый сценарий через Telegram, а не только API или классы.
- [ ] Состояние и права доступа пользователя проверяются на Application boundary.
- [ ] PostgreSQL — источник истины; LLM не изменяет его непосредственно.
- [ ] Сбой и повторный запрос не создают повреждённое/дублированное состояние.
- [ ] Обновлены миграции, тесты, пользовательская/техническая документация по необходимости.
- [ ] `dotnet build` и релевантные `dotnet test` выполнены; результаты указаны в отчёте.
- [ ] Отсутствуют секреты в логах; изменения доступны без визуальных предпосылок.
- [ ] Нет преждевременной инфраструктуры для будущих milestones.
- [ ] Отмечены фактически закрытые acceptance checks и статус milestone.

## 3. Правила изменения плана

План допускает уточнение после анализа кода и результатов каждого milestone. Изменения должны быть явными: причина, затронутые требования, последствия для уже реализованного поведения и тестов. **Нельзя молча удалять требования ТЗ ради упрощения реализации.** Если milestone блокируется отсутствующей моделью проекта, LLM provider или scheduler, Codex предлагает минимальную зависимость либо перенос конкретной интеграции на предусмотренный milestone. Важные архитектурные решения фиксировать коротким ADR, если в репозитории принята такая практика.
